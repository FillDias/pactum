# Legacy `receitas` table still unioned into Saldo

`app/services/saldo_service.rb` in pactum-api computes `total_receitas` as `Receita.where(...).sum(:valor) + Lancamento.where(tipo: 'receita', ...).sum(:valor)` — it sums two tables, not one. `config/routes.rb` has no `/receitas` route and no controller exposes the `Receita` model, so nothing can write new rows into `receitas` via the API today; all new income goes through `/lancamentos`. The `receitas` table appears to predate the app's consolidation onto `Lancamento.tipo == 'receita'` as the single write path — the same consolidation the mobile client was just fixed to actually honor (it had its own parallel `Receita` store/type that never fed into Saldo; see `docs/financas/CONTEXT.md`). The union in `SaldoService` was left in place — deliberately or not — so any pre-existing rows in `receitas` keep counting toward Saldo instead of silently dropping out.

Do not delete the `Receita` model, the `receitas` table, or the union in `SaldoService` without first confirming the table is actually empty (or migrating its rows into `lancamentos`) in production. Until then, treat this as a read-only legacy source that Saldo depends on, not dead code safe to remove.
